
### 实现思路

```mermaid
flowchart LR
  A[解析参数] --> B[检索收集]
  B --> C[格式整理]
  C --> D[打印输出]
```

1. **解析参数**
由 parse.c / parse.h 负责。
程序启动后首先解析命令行，识别：
`OPTION`：控制匹配或输出格式
`PATTERN`：检索目标
`FILE`：输入文件列表

2. **检索收集**
由 search.c / search.h 负责。
该模块按块 read 文件内容，将数据拆分为行，并对每一行执行匹配。匹配成功的行会被记录下来。
采用逐块读取而不是一次性加载整个文件，可以降低大文件场景下的内存占用。

3. **格式整理**
由 arrange.c / arrange.h 负责。
根据选项，把匹配行整理成最终输出格式。例如是否附加行号、是否只输出计数、是否包含文件名等。

4. **打印输出**
由主流程或输出相关逻辑完成最终打印。lrg.c 负责初始化各模块、串联流程，并在结束时汇总退出码。

5. **错误处理**
错误分为用法错误和系统错误
当遇到用法错误时，先会报告错误，并逐层回退至`main`函数，依次释放资源
当遇到系统错误时，仅会报告错误，然后继续执行
### 模块划分

| 文件 | 职责 |
| --- | --- |
| `lrg.c` | 程序入口，初始化各模块，汇总退出码 |
| `parse.c` / `parse.h` | **参数解析** 识别`OPTION`、`PATTERN`、`FILE` |
| `search.c` / `search.h` | **检索搜集** 逐块 `read` 文件，拆行，匹配，记录匹配行 |
| `arrange.c` / `arrange.h` | **格式整理** 根据选项把匹配行格式化成最终输出 |
| `mstring.c` / `mstring.h` | 动态字符串，负责拼接与扩容 |
| `error.c` / `error.h` | 统一报告错误 |



### 构建与测试
- 使用**make**进行构建
```make
make
```

构建成功后，将在根目录下生成`lrg`可执行文件

- 使用**make test**进行测试
```make

make test
```
将自动构建并运行测试脚本`run_tests.sh`，输出测试结果

- 使用**make clean**清理构建产物
```make
make clean
```

## 运行
用法:
```
.\lrg [-nic] PATTERN [FILE...]
```
当不传`FILE`参数时，会自动读取`stdin`
